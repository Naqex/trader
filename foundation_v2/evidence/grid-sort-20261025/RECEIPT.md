- Sort state belongs to the current table view, not stored column preferences. A new view starts with no explicit sort.

## Data flow and API compatibility

Header interactions → ordered `sort=[{key,direction},…]` query → validate → filter/sort the full table projection → count/page slice → render positional `#`. Each comparator keeps null last, uses the next key only for ties and finally preserves source index. `sort=[]` keeps source order. Changing sort resets page1. Cache/snapshot distinguish sort order, direction and clear state.

Rust and Python support the same optional query and response `sorts`; old callers omitting it retain the legacy sort contract. Keys/directions/duplicates/length are validated. No stored trade, financial metric or broker execution behavior changes.
